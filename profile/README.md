<p>配环境配到一半卡住，最耗时间的不是改，而是不知道该改哪一层。这篇按故障树来写：先把症状分三档——连不上、连得上但页面不对、能登录但状态互相污染，每一档对应一条排查分支，分支里列出检查动作和判定结论。三条分支最后收敛成三条隔离规则，照这三条重配一遍，多数串号和泄漏问题会一起消失。</p>

<h2>一、先给症状分档，别一上来就重装</h2>
<p>症状分档的意义是缩小范围。同样是"打不开"，代理没生效和 DNS 解析错误要改的地方完全不同，先分档能省掉一半无效操作。</p>
<h3>三档症状的边界</h3>
<p>第一档连不上：请求超时、连接被拒、返回 407。第二档连得上但不对：页面语言不符、地区跳转、显示的是别的城市。第三档能用但脏：两个账号互相顶下线、A 号看到 B 号的历史、退出一个另一个也退出。</p>
<h3>每档的第一个动作</h3>
<p>第一档先跑 curl 直连代理端口，看返回码；第二档先看 ipinfo 与 ipleak 的出口和 DNS 是否一致；第三档先查配置文件目录是不是被复制过。三个动作都在一分钟内能做完，先做再谈其他。</p>

<h2>二、分支一：代理层为什么没生效</h2>
<img src="/tp.png" alt="家庭住宅IP代理连通性排查与DNS泄漏检测步骤">
<h3>先确认代理本身通不通</h3>
<p>curl -x http://用户:密码@主机:端口 -s https://ipinfo.io/json，返回的 ip 字段应当等于代理出口。返回 407 是鉴权失败，检查密码里是否有特殊字符没转义；返回超时多半是端口或防火墙；返回的 ip 仍是本地地址，说明代理没被使用。SOCKS5 要用 --socks5-hostname，让域名在远端解析，否则 DNS 还是走本地。</p>
<h3>三种常见"看起来生效了"</h3>
<p>一是浏览器装了代理插件但只对部分站点生效，PAC 规则里漏了目标域名；二是系统代理设了，但应用走自己的网络栈，不读系统设置；三是 WebRTC 绕过了代理，页面里仍能拿到本地地址。第三种用浏览器打开 WebRTC 检测页，看候选地址里有没有本地网段，有就说明漏了。</p>

<h2>三、分支二：浏览器环境层的三类矛盾</h2>
<h3>语言、时区、地理定位</h3>
<p>三者要指向同一地区。语言看请求头，时区看系统设置，地理定位看浏览器权限。地理定位这一项容易被忽略：允许了定位却没改坐标，页面拿到的经纬度还在本地，和出口城市对不上。</p>
<h3>渲染与硬件特征</h3>
<p>分辨率、缩放比例、字体列表、WebGL 渲染器字符串，这些在同一台机器上的多个配置文件之间是共享的。要求不高时不必逐个改，但要意识到它们无法通过多开配置文件区分，需要更高的隔离档位才能分开。</p>
<h3>扩展与同步</h3>
<p>登录了浏览器账号并开启同步，书签、扩展、甚至部分偏好会跨设备同步，等于把两个环境连起来。用于账号操作的配置文件，建议关闭同步，扩展只留必要的一两个。</p>

<h2>四、分支三：Cookie 与存储串号的判定</h2>
<h3>清 Cookie 不等于清干净</h3>
<p>localStorage、IndexedDB、Service Worker 缓存、会话恢复记录都可能保留身份信息。只清 Cookie，页面仍可能从 IndexedDB 里恢复登录态。清理时勾选"Cookie 及其他网站数据"，并在站点设置里确认没有残留的存储项。</p>

<h3>复制目录是串号的头号原因</h3>
<p>为了省事复制一份配置目录，看起来是两个环境，实际上 Cookie、存储、指纹全都一样，只是窗口不同。正确做法是新建配置文件，再手动调整设置，宁可多花十分钟。</p>

<h2>五、把故障树收敛成三条隔离规则</h2>
<h3>规则一：一账号、一配置、一出口</h3>
<p>三者一一对应，写在绑定表里。任何一项变动都记时间，出问题时能立刻判断是哪个维度变了。</p>
<h3>规则二：新建而不复制</h3>
<p>新增环境一律新建配置文件，改语言、时区、代理三项，其余保持默认。复制目录省下的时间，会在排查串号时加倍还回去。</p>
<h3>规则三：清理要清到底</h3>
<p>清理时按"站点全部数据"处理，并检查 Service Worker 是否注销。清理完刷新一次，确认登录态确实消失，再切下一个账号。</p>

<h2>常见问答</h2>
<h3>代理插件显示已连接，为什么 ipinfo 还是本地 IP？</h3>
<p>答：插件可能只对部分标签页或部分协议生效，也可能被 PAC 规则排除。用 curl 直连代理验证一次，如果 curl 正常而浏览器不正常，问题就在浏览器侧的规则，不在代理本身。</p>
<h3>每个账号都要单独装一个浏览器吗？</h3>
<p>答：不一定。同一浏览器的多个配置文件就能满足多数场景，前提是每个配置文件配独立出口、不复制目录、不开同步。账号价值很高时再考虑独立虚拟机。</p>
<h3>无痕窗口能替代独立配置文件吗？</h3>
<p>答：不能。无痕只隔离本地存储，出口、时区、语言、字体都没变，多个无痕窗口之间还共享同一出口。</p>
<h3>怎么确认 DNS 没有泄漏？</h3>
<p>答：打开 ipleak.net，看 DNS 段显示的解析服务器所属国家。与出口国家不一致即为泄漏，处理方式是改用全局代理，或启用安全 DNS 指向同区解析服务。</p>

<h2>合规提示</h2>
<p>本文提供的是网络与环境配置的排障方法，用于恢复自有账号的正常使用，不涉及绕过平台审核。使用代理与浏览器自动化工具须遵守服务商条款与所在地法律法规。</p>
<p>环境隔离的目的是避免误操作导致的数据混淆与账号风险，不应被用于冒充他人或规避平台对多账号的管理规定。</p>
